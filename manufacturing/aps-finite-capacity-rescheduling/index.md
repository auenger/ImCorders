# APS 如何处理物料、产能、换型和插单

作者：杨正武
来源：https://imcoders.cn/manufacturing/aps-finite-capacity-rescheduling/
发布：2026-10-14T00:00:00.000Z

从风机尾批任务与一张急单出发，拆解 APS 的输入快照、有限产能、物料、日历、换型和冻结规则，比较三种排程方案，并记录候选评审、ERP 与 MES 发布回执、实绩重排和 Agent 接入的验收边界。

---


[订单延期篇](/manufacturing/order-delivery-delay-analysis/)把尾批开工写成了物料与资源同时满足后的时点。现场要进一步决定任务先后、具体资源和开始时间时，还会遇到班次、换型、已开工任务与新来的急单。

这一篇进入 APS（高级计划与排程），用一个可手算的样本比较候选方案，再看方案怎样交给 ERP、MES。样本沿用风机尾批的业务背景，另设任务工时和相对小时，不重放前文的 D 日历，也不改写既有订单的实际记录。

## 排程先确定要安排哪些任务

### 供需数量、工序安排和执行状态分别核对

ERP 可以保存需求、生产订单和供给关联，MRP 可以计算物料需求与补货建议。排程还要把工序任务放到满足条件的资源和时间区间中。不同 ERP 本身也可能提供有限产能或详细排程能力，不能只凭产品缩写判断它是否考虑产能。

APS 需要明确本次范围：哪些工单、哪些工序、哪些资源，以及覆盖多长时间。计划员按整张工单排顺序，与按工序实例选择设备，使用的数据粒度不同。只给任务一个总工时，可能掩盖中间工序和资源切换。

Microsoft 的[详细作业排程说明](https://learn.microsoft.com/en-us/dynamics365/supply-chain/production-control/job-scheduling)区分工序层面的安排与更细的任务拆解，并描述有限产能、物料和具体资源的考虑。本文借此落实输入粒度，不将某个产品的字段当作所有 APS 的统一模型。

| 输入 | 至少需要确定的内容 | 缺少时可能出现的问题 |
| --- | --- | --- |
| 需求与交期 | 数量、需要节点、承诺版本、优先规则 | 把工序完成当作客户交付，或优化错目标 |
| 工艺与任务 | 先后关系、工时、批量、允许拆分与转移规则 | 后工序提前开始，或把不能中断的任务切开 |
| 物料 | 适用批次、可领状态、分配与预计可用时间 | 有到货记录却无法实际开工 |
| 资源 | 资格、产能单位、日历、已有占用与效率依据 | 空闲设备不具备能力，或同一资源重复占用 |
| 换型与辅助条件 | 产品族、前后状态、工装及合格人员 | 忽略换型，或多台设备争用同一副工装 |
| 现场实绩 | 已开工、已完成、暂停、剩余量与预计剩余工时 | 重排已发生的动作，或重复安排全部任务 |

### 输入快照保留版本、来源和不确定性

物料状态、设备占用和订单优先级会持续变化。一次计算应保存使用的输入版本、查询时间、来源及模型假设，避免将上午的库存、下午的资源日历和另一版工艺混在一起。

预计到料与已经可领需要分开。本次计划如果把预计到料作为允许条件，就要暴露这项依赖，并在执行前复核；不能让一个尚未确认的日期在输出中变成确定可用的库存。

工时也要有适用范围。历史平均值可以支持估算，但产品配置、设备、班组或批量变化后，实际节拍可能不同。候选计划应保留采用的工时与效率依据，后续用实绩核对，不能把排程结果的精确到分钟误当成预测已经准确。

## 物料、日历和换型要在同一模型里成立

### 有限产能约束要落到具体资源

一台只能同时处理一个任务的设备，需要检查占用区间是否重叠。两台设备各有两小时空档，也不一定能接住一个必须连续运行三小时的任务。资源组汇总的小时数，还要继续拆到实际可选设备、资格和连续窗口。

[Microsoft 的有限产能说明](https://learn.microsoft.com/en-us/dynamics365/supply-chain/master-planning/planning-optimization/finite-capacity)描述了产能不足时任务需要移到可用时段、日期可能后移的行为。有限产能计算能够揭示冲突，交期能否满足仍取决于资源与其他条件。

Google 的 [Job Shop 示例](https://developers.google.com/optimization/scheduling/job_shop)把工序先后和同一机器上的不重叠作为基本约束。现场还需继续加入本次启用的日历、物料、换型、辅助资源与冻结规则，不能直接将一个简化算法示例等同于完整工厂模型。

### 日历约束同时作用于加工和必要准备

设备、人员、工装与检验资源可能有不同日历。若一个任务同时需要设备和合格操作员，只有设备空闲还不够。维护窗口、休息、停产与已占用时段，也要按实际规则参与计算。

任务能否跨休息时间、能否暂停后继续、最小转移批量是多少，需要显式定义。允许拆分时还要记录拆出的任务、剩余量与额外准备；不能让求解过程为了塞进空档，自动改变本来不允许中断的工艺。

### 换型时间取决于前后状态

从 A 族切换到 B 族，与从 B 切换回 A，耗时可以不同。同一族连续生产也可能仍需要清理、换刀或首件检查，具体规则应由工艺与现场确认。

换型占用什么资源，能否提前准备，是否必须等物料到位，休息或隔夜后是否保留准备状态，都会改变可排区间。产品族相同就默认零换型，只能作为明确批准的样本前提，不能成为所有产线的默认规则。

交期可以作为允许一定偏差的优化目标，资格、质量限制和不可重叠等则按企业批准的模型作为必须满足的条件。改变这些业务条件需要相应批准，不能仅把违反条件的惩罚调高一点，就允许排程越过限制。

## 同一张急单可以形成哪些候选方案

### 先固定一个独立的小时样本

以下仅模拟装配工位上的任务，T 代表一项 20 台尾批装配任务，U 代表新增急单。完成时点只指本段工序结束，不包含后续终检、仓储和客户签收；工时不能用来推算前文整张风机工单的真实产能。

以样本工作日 08:00 为相对小时 h0，h24 表示次日 08:00。主设备 `ASM-01` 及本段所需操作员的可用窗口为 `[0,4)`、`[5,9)`、`[24,28)`、`[29,33)`。h4 至 h5 休息，h9 至 h24 不工作；任务可以恰好在窗口终点结束。

| 任务 | 产品族 | 加工时长 | 物料最早满足 | 本段工序期望完成时点 |
| --- | --- | --- | --- | --- |
| F，已开工任务 | A | 本次固定占用 `[0,2)` | 已满足 | 保持当前安排 |
| T，20 台尾批 | B | 3 小时 | h2 | h7 |
| U，新增 10 件急单 | A | 2 小时 | h0 | h4 |

在 h1 收到插单请求并形成快照。F 已开工，后续预计占用到 h2，本次计算将它冻结；新任务从快照时点以后安排。若实际剩余工时或设备状态再变化，需要新一轮计算。

样本进一步固定以下规则：设备初始为 A；A→B 和 B→A 换型各 1 小时，同族换型为 0。换型和加工都占用主设备与所需操作员，各自不可中断，只能落在可用窗口内。换型不得早于对应物料可用，完成后的状态在休息和隔夜期间保留。本例只核对这些规则，没有额外工装冲突。

### 保尾批与先急单会产生不同结果

S1 先安排 T。F 到 h2 结束，T 的换型放在 `[2,3)`。剩下的 `[3,4)` 只有一小时，不能容纳不可中断的三小时加工，所以 T 在 `[5,8)` 加工。随后 `[8,9)` 从 B 换回 A，U 只能等到次日 `[24,26)` 加工。

S2 先安排 U。设备仍为 A，U 在 `[2,4)` 加工，h4 完成。休息后在 `[5,6)` 为 T 换型，再在 `[6,9)` 加工 T。急单满足了本段 h4 的期望，T 则比 h7 晚两小时。

| 方案 | F | U 加工区间 | T 换型及加工 | 本段结果 |
| --- | --- | --- | --- | --- |
| S1，先 T | `[0,2)` 冻结 | B→A 换型 `[8,9)`，加工 `[24,26)` | A→B `[2,3)`，加工 `[5,8)` | T 完成 h8，U 完成 h26 |
| S2，先 U | `[0,2)` 冻结 | 同族免换型，加工 `[2,4)` | A→B `[5,6)`，加工 `[6,9)` | U 完成 h4，T 完成 h9 |

两个方案都保留了本次的硬约束，却没有同时满足两项期望完成时点。它们是人工构造并逐条核对的候选，不是运行求解器后得到的全局最优证明。

用连续小时计算本段延期，`延期 = max(0, 完成时点 − 期望完成时点)`，休息和隔夜不从偏差里扣除。S1 的 T 晚 1 小时、U 晚 22 小时；S2 的 T 晚 2 小时、U 不晚。这个口径与“超出多少工作小时”不同，报表里应写清。

### 增加合格资源要单独说明新前提

再构造 S3：允许使用另一台已完成资格确认的 `ASM-02`，初始为 B；它与独立的合格操作员在 `[3,7)` 连续可用，期间没有主设备那段休息限制。物料和其他要求也已满足。这样 T 可以免换型在 `[3,6)` 加工，U 仍在 `ASM-01` 的 `[2,4)` 加工。

S3 的 T、U 都能满足本段期望，但它改变了资源前提。设备资格、人员、特殊窗口、成本和授权必须分别确认，不能只因为甘特图上有一台空设备，就认定它能够替代。

| 方案 | T 延期 | U 延期 | 示例指标 `T延期 + 5×U延期` | 新增资源条件 |
| --- | --- | --- | --- | --- |
| S1 | 1 小时 | 22 小时 | 111 | 无 |
| S2 | 2 小时 | 0 | 2 | 无 |
| S3 | 0 | 0 | 0 | 另增合格设备、独立人员与连续窗口 |

这个加权指标只是演示如何表达偏好，不对应违约金或真实经营损失。S3 分数更低，还需比较新增资源代价与落实可能性；S1、S2 则要说明各自影响了哪张订单。换型最少、完工最早、延期最小和计划最稳定，可能给出不同选择。

求解结果也要说明状态。[Google CP-SAT 文档](https://developers.google.com/optimization/cp/cp_solver)区分已证明最优、找到可行解、已证明不可行、模型无效及尚无结论等情况。限时没有找到方案，不能直接写成工厂一定排不下；找到可行方案，也不能省略模型范围就宣传为最优。

## 重排怎样成为车间能够执行的计划

### 先核对已执行范围和允许调整的部分

设备故障、质量挂起、缺料、插单或报工偏差，都可能触发新计算。重排应先读取当前已完成量、已开工区间、预计剩余工时及未结任务，避免把整个原始任务重新安排一遍。

已经开工的 F 在本例中保持冻结。其他场景还可能冻结已备料、已完成换型或即将开工的任务；冻结窗口与可移动范围属于业务规则。尚未开工也不代表调整没有代价，仓库可能已经配送，工装与人员可能已经预约。

重排输出至少包括哪些任务改变了资源、时间、顺序或批量，影响哪些上下游任务与订单，以及仍有哪些条件没有落实。每次重排都追求局部交期更早，可能让现场频繁搬料、换型和改派，因此还要比较计划变动范围。

### 候选、批准和下游应用分别保存版本

本例可将 S2 保存为候选 `APS-S2-01`，关联输入快照和目标偏好。评审时核对 U 被提前、T 被延后，固定任务 F 保持原安排。计划岗位选择后，再按权限与约定发布给 ERP、MES，必要时同步备料需要时间。

下面只表示候选数据片段，所有字段均为概念结构，不对应厂商 API，也没有执行发布：

```json
{
  "plan_id": "APS-S2-01",
  "status": "CANDIDATE",
  "input_snapshot": "INPUT-APS-07",
  "expected_execution_revision": "E12",
  "time_basis": "sample_relative_hours",
  "frozen_tasks": ["F"],
  "tasks": [
    {
      "task": "U",
      "resource": "ASM-01",
      "run_start": 2,
      "run_end": 4,
      "quantity": 10,
      "unit": "EA"
    },
    {
      "task": "T",
      "resource": "ASM-01",
      "setup_start": 5,
      "setup_end": 6,
      "run_start": 6,
      "run_end": 9,
      "quantity": 20,
      "unit": "EA"
    }
  ]
}
```

U 的加工时长按表中的整项任务参数计算，没有据此建立通用节拍。完整契约还需来源任务映射、工序版本、辅助资源、日历版本、修改范围、审批引用与幂等身份。

发布前应与最新对象状态比较。如果 MES 已经改变派工，或者 F 的剩余工时发生变化，就需要按规则重新核对受影响的差异，不能用候选里的预期区间覆盖当前执行事实。

### 部分应用失败时保留各系统的实际结果

ERP 接受新时间，MES 因工序状态变化拒绝应用，是可能存在的中间结果。发布台账应标出每个目标的接受范围、拒绝原因、目标版本和未落实任务，不能只显示一个笼统的“发布成功”。

按企业批准的规则，可以暂停相关新任务释放、处理冲突后补发，或批准新的局部方案。相同发布身份与相同内容重试时，应能够查到已有结果；内容改变则形成明确的新版本，避免重复建立任务或覆盖另一轮修改。

撤销候选或恢复旧计划，不会自动撤销已经发生的领料、换型、开工与实物移动。恢复时要重新核对当前事实，再决定可以撤回哪些未执行安排、哪些需要补偿或另行批准。

## 怎样验收排程结果并让 Agent 参与

### 用小样本检查硬约束和计划变动

可以先人工核对本文三个方案，再选真实岗位认可的样本覆盖多工序、共享资源和异常恢复。每项验收同时保留输入、约束配置、候选区间与检查结果，不能只验收画面上是否出现了甘特条。

| 验收情形 | 应看到的结果 |
| --- | --- |
| T 物料 h2 才满足 | 本例不允许在 h2 前为 T 换型或加工 |
| h4 至 h5 休息、加工不可中断 | 不把三小时加工直接排成 `[3,6)` 放在主设备上 |
| S1 的换型已在 h3 完成 | 保留 B 状态，T `[5,8)` 加工后再换回 A |
| S2 插入 U | F 不移动，U `[2,4)`，T 换型 `[5,6)`、加工 `[6,9)` |
| 候选使用 ASM-02 | 同时核对设备资格、独立人员、特殊窗口与批准条件 |
| 两台设备共用同一工装或人员 | 纳入辅助资源冲突，不能仅检查设备不重叠 |
| 限时未找到方案或发现模型错误 | 区分尚无结论、不可行与模型无效，不伪造成功计划 |
| 快照之后已有任务开工或状态变化 | 发布前重新校验，保留已执行记录和剩余范围 |
| ERP 与 MES 只接受一部分 | 各自结果可查询，相关任务按批准规则处理 |
| 同一发布重试或迟到旧版本到达 | 不重复建任务，不静默覆盖较新的目标基线 |

涉及加班、允许跨班加工、替代资源或批量拆分时，应作为新方案条件单独记录。它们可能改善结果，也会改变成本、质量依据和现场安排，不能在计算过程中悄悄启用。

### Agent 先整理约束与解释候选差异

适合从“为什么 T 不能在 h3 直接加工三小时”开始。Agent 读取物料时间、主设备日历、不可中断规则与已占用区间，指出 h4 至 h5 的休息窗口，再关联到允许的候选。

比较 S1 与 S2 时，Agent 可以列出任务区间、换型次数、延期口径和受影响订单；比较 S3 时，应指出新增资源条件，避免把改变约束后的结果包装成同一前提下的算法提升。每条结论附来源对象、输入版本、读取时间与所用规则。

Agent 可以生成缺失输入清单、冲突解释、候选对比和评审草稿。模型生成的自然语言顺序，还需经过排程约束检查；发布、改派、解除冻结和改变资源资格分别走授权业务动作，执行后保存目标回执。

这篇先把排程输入、手算候选和执行交接留下。下一篇进入 QMS、LIMS 与质量放行，继续拆检验结果、处置权限和库存限制怎样影响生产与交付。目录进度保留在[制造业研究目录](/blog/2026-10-14-manufacturing-systems-map/)，计划与执行关系可以回到[数据地图](/manufacturing/data-map/#product-orders)查看。
