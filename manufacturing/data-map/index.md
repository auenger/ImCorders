# 制造业系统数据地图

作者：杨正武
来源：https://imcoders.cn/manufacturing/data-map/
发布：2026-10-14T00:00:00.000Z

用五张交互地图连接产品、订单、物料、质量、设备和组织数据，明确系统之间传递的对象、版本、状态与回执，作为制造业系统深度拆解的起点。

---


制造业系统的名字容易记住，系统之间的数据关系更值得逐项核对。ERP 下达一张生产订单，MES 收到的未必是同一种“工单”；WMS 看见库存，也还要检查批次、冻结、预留和检验状态。

这份地图从这些交接处开始。先用离散制造参考场景建立五个视图，再用下面的契约表说明主要输入、回传和责任边界。它是一份研究与讨论用的参考模型；每家企业的模块划分、接口方式和状态规则还需要现场确认。

| 视图 | 阅读顺序 | 独立地图 |
| --- | --- | --- |

| 物料与物流 | 到货承诺、收发需求、仓库任务、厂内配送与客户签收 | [打开物料与物流地图](/manufacturing/maps/materials-logistics.html) |

交互地图由 archify 的 dataflow 模式生成，可以独立打开、切换主题并导出图片或 SVG。站内页面提供视图切换和文字流转清单，手机页面直接显示流转清单，交互地图可在独立窗口打开。阶段标题表示本视图的阅读顺序，不对应 ISA-95 的层级或网络分区。

同一系统可能在一张图里出现多次。例如“ERP 订单视角”和“ERP 核算视角”用于区分数据的下达和回收，实际可以是同一个 ERP 实例。MES 中的工艺定义、工单执行与版本适用也有类似情况。没有箭头的两个节点之间，不推断存在直接接口。

首版图上突出主路径，部分回执和侧向输入写在下表中。后续拆到具体场景时，再把请求、接受、完成、拒绝和补偿逐一画开。

## 系统交接时究竟传什么

### 产品定义和订单不能只传一个编号

图纸发布、工艺生效和生产下达是不同的业务事件。现场需要拿到对当前物料、配置、工单和时间适用的版本。系统中存在一份工艺文件，无法直接说明它已经获准用于这张工单。

| 方向 | 主要数据契约 | 必须确认的条件或回传 |
| --- | --- | --- |
| CAD / PDM → PLM | 模型、图纸、设计版本、产品结构关联 | 发布状态、文件校验与关联物料 |
| PLM → ERP | 物料、BOM、配置、替代关系和变更生效条件 | 谁维护哪些字段，ERP 是否接受该版本 |
| PLM / CAPP → MES | 制造结构、路线、工序、参数与作业文件 | 工厂、产品、工单的适用范围；下发接受或拒绝 |
| CRM / CPQ → ERP | 客户配置、订单行、数量、承诺日期 | 配置是否可生产，订单变更如何处理 |
| ERP → APS | 生产需求、交期、优先级和物料需求 | 计划基线、日历、在制状态与约束数据的更新时间 |
| APS → MES | 经批准的作业计划、资源分配、顺序与时间窗口 | MES 接受结果、无法执行的原因与重排规则 |
| MES → ERP / APS | 产出、报废、消耗、工时、进度与资源变化 | 区分回到 ERP 的业务过账与回到 APS 的执行约束 |

这张图采用 PLM 管产品定义、工艺规划生成执行依据的部署假设。MBOM 可以在 PLM、ERP 或其他制造规划模块中形成，专题会按实际企业说明其维护位置。PLM、MES、ERP 贯通的产品与制造协同，可参考 [Siemens 的闭环制造介绍](https://webinars.sw.siemens.com/en-US/closed-loop-manufacturing-for-defense/)。

ERP 与执行系统之间的下达和回报，需要单独确认消息类型。[SAP Digital Manufacturing 集成指南](https://help.sap.com/doc/f6b2ab2222794bebad4c0dcd33138e71/latest/en-US/SAP_DMC_Integration_Guide_enUS.pdf)提供了生产订单、产出与报废确认、货物移动等接口的具体例子；本文没有把这些产品接口当作所有企业的固定实现。

### 库存要能解释位置和可用条件

同一批货可能已经到厂，仍在待检区；可能完成上架，却已经被别的订单预留。缺料分析需要把这些状态带到同一口径里。

| 方向 | 主要数据契约 | 必须确认的条件或回传 |
| --- | --- | --- |
| SRM → ERP / WMS | 供应商承诺、到货通知、采购单行与批次信息 | 承诺日期与实际收货分开记录 |
| ERP → WMS | 采购收货、生产领退料、成品入库与发运需求 | 单据行、单位、仓库、批次规则与业务状态 |
| MES ↔ WMS | 工单需求、配送请求、发料、退料和实耗关联 | 送达、领用、消耗分别由谁确认 |
| WMS ↔ WCS / WES / 车队 | 搬运任务、来源目的位置、载具与优先级 | 接受、开始、完成、失败；重复任务如何去重 |
| QMS / 质量模块 → WMS / MES | 经授权规则形成的放行、隔离、返工或报废决定 | 决定范围、批准人或自动规则、限制生效结果 |
| WMS ↔ TMS / YMS | 发运交接、装卸、运单与园区作业状态 | 出库、装车、离厂与签收各自的业务时间 |
| WMS / MES → ERP | 收发存、产出和耗料的确认记录 | 物理完成与财务过账的差异、失败与对账状态 |

图中的 WES、WCS 和车队调度合并表示物流执行能力，不规定它们的内部串联关系。实际项目需要继续拆到“哪个系统创建任务、哪个系统控制设备、哪个系统确认完成”。

### 检验完成以后还要形成处置

LIMS 和检测设备提供样品或产品的测量结果。QMS 或业务系统中的质量模块，再根据授权和规则形成处置。库存与生产系统接收决定后，分别落实对应限制。

[SAP 对检验批使用决策的说明](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/2bc3ee8d1c83404e8cf62418640004f2/3a7fb6535fe6b74ce10000000a174cb4.html)展示了这一区别：结果记录、特性关闭、权限和当前状态，都会影响能否做出使用决策。具体产品也可以按预先配置的规则执行自动决策。

质量追溯还需要记录批次分拆、合并、替代、返工和序列号关联。只保存最终检验结果，往往无法回到发生异常的工序和物料投入。首版将谱系画成独立的数据角色，实际可以由 MES、专用追溯系统或数据平台承接。

质量分析输出的是原因调查材料和改进建议。要改变工艺、检验计划或物料版本，继续走相应的变更和生效流程。

### 设备信号需要补上业务上下文

一条温度或报警记录，至少还需要知道来自哪台设备、采用什么单位、何时采集、数据质量如何，以及当时正在执行哪张工单。Historian 保存历史时序，MES 等运营系统提供工序、批次和班次关联。

故障事件进入 EAM 或 CMMS 后，可以产生检查和维修任务。维修结束、设备具备运行条件、重新进入排程日历，也需要分别确认。产能反馈可以来自 MES，也可以通过排程集成直接使用维护日历，图中展示的是一种逻辑分工。

能源分项分析还需补充计量边界、生产数量、班次和分摊依据。设备地图只画出主要来源，BI、EPM 和 EHS 是不同用途的下游使用者，具体读取范围由业务决定。

这里没有画通用 Agent 直接写 PLC、DCS 或 SIS 的路径。现场控制、联锁与安全保护有独立的工程职责，后续讨论控制系统时会另外说明。

## 把五张图接起来靠哪些共同对象

系统连接完成以后，名称、编码和时间仍然可能对不上。首版先保留下面七组关联键，后续专题再展开字段字典与状态映射。

| 对象 | 跨系统关联所需的信息 | 容易遗漏的差异 |
| --- | --- | --- |
| 物料与产品 | 来源系统、物料编码、版本、配置、单位 | 同码不同版、异码同物、单位换算 |
| 订单与任务 | 销售单行、生产订单、工单、工序、任务 ID | 一张订单拆成多个工单，撤销后重建 |
| 批次与序列号 | 原料批次、生产批次、单件身份、投入产出关系 | 分批、合批、返工和替代用料 |
| 工艺与文件 | 路线版本、程序版本、文件版本、生效与适用范围 | 文件已发布但不适用于当前工单 |
| 库存与物流 | 工厂、仓库、库位、批次、载具、状态和预留 | 在库量、可用量、在途量和实物位置 |
| 设备与人员 | 资产编号、采集点位、资源组、人员身份与技能资格 | 设备在线但不可排产，人在岗但资格过期 |
| 事件与决定 | 事件 ID、业务时间、接收时间、来源版本、处置依据 | 补录、补传、重复、乱序和决定未落实 |

[ISA-95](https://www.isa.org/standards-and-publications/isa-standards/isa-95-standard)为制造运营与企业业务之间的信息交换提供对象和活动模型。首版沿用其区分计划、运营与控制职责的思路，同时保留供应商、研发和组织协同等站点研究范围。

数据与协同视图上排展示一种加工路径，可以使用 API、消息、文件或数据副本实现。Agent 做跨系统查询时也可以通过受控连接器直接读取来源系统，不要求将全部工业数据搬到同一个平台。

下排展示业务动作的执行条件。人员资格、受控文件、身份权限、审批和状态前置条件需要在实际动作入口校验；建议进入执行时同样遵循这些条件。调用成功后还要记录业务是否接受、状态是否完成，以及失败后如何恢复。

## 本版边界与下一步内容

这一版覆盖主要系统族之间的逻辑数据流。它没有规定消息中间件、数据库、网络拓扑、接口实时性或厂商选型，也没有把所有分析消费者的侧向输入画满。图中的角色可以由独立系统、ERP 模块或 MES 扩展实现。

首批后续内容按 [研究目录](/blog/2026-10-14-manufacturing-systems-map/)中的编号推进：M01 的[产品结构与工程变更](/manufacturing/plm-engineering-change/)，M02 的订单和经营记录，M03 的 MES 工单生命周期，M04 的库存和生产配送，以及 S02 的订单延期分析。它们发布后，会从[制造业系统模块](/manufacturing/)进入。

流程制造还要补配方、批次执行与电子批记录，连续过程还需展开 DCS 与物料平衡。批次部分将参考 [ISA-88](https://www.isa.org/standards-and-publications/isa-standards/isa-88-standards)，分别注明案例的行业、工段和部署假设。

地图源文件以 JSON 保留，站点上的五张 HTML 与源文件一一对应。后续修订会同时更新箭头、数据契约和说明，并记录实质修订日期。
