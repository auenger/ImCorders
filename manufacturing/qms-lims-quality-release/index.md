# QMS、LIMS 与质量放行的衔接

作者：杨正武
来源：https://imcoders.cn/manufacturing/qms-lims-quality-release/
发布：2026-10-14T00:00:00.000Z
更新：2026-10-14T00:00:00.000Z

沿用风机订单中的 20 件待检支架与两台返工产品，拆解 QMS、LIMS、MES 和 WMS 之间的检验依据、样品范围、质量处置、放行授权、库存限制、复检记录与接口回执，并给出可执行的集成验收场景。

---


[WMS 篇](/manufacturing/wms-inventory-production-delivery/)里，新支架已经收货 160 件，其中 140 件可领，20 件还留在待检范围。到了 [MES 篇](/manufacturing/mes-work-order-lifecycle/)，又有两台风机因为支架装配损伤被挂起，经过换件、复检后才进入合格品。

仓库想知道能不能发料，计划员想知道何时可用，质量人员需要确认检验依据和处置权限。几个岗位看着同一批实物，却在回答不同的问题。只同步一个“合格”字段，很容易让这些问题混到一起。

本文继续使用这组模拟业务，沿着检验任务、结果复核、质量处置和执行回执往下追。新增的单据编号用于说明关联方式，不对应真实工厂记录；检验项目、抽样方法与判定限值应来自企业批准的要求，本文不另造一套检验标准。

## 一件物料可用之前要核对哪些记录

### 检验结果和使用资格各有范围

先把尾批支架找出来。`LOT-N03` 是新支架 `BKT-018` 的 20 件收货批次，位于待检位置 `QC-01`；前两批 `LOT-N01` 的 100 件与 `LOT-N02` 的 40 件已经放行。旧支架 `BKT-017` 的 80 件仍受工程变更适用范围限制，不能因为新支架检验通过就解除旧料的限制。

检验结果回答某次检验做了什么、测得什么、依据哪个要求判定。质量处置回答这个对象下一步怎样处理，可能接受、拒收、返工，或进入额外评审。库存资格还要检查位置、预留、其他隔离和具体业务用途。成品能够进入下一工序、能够入库、能够出货，也可能分别有不同条件。

可以给这 20 件支架建立一项模拟检验任务 `IQC-0020`，关联收货行、批次、物料版本和本次覆盖数量。即使执行时只抽取部分样品，检验数量、判定覆盖数量和库存限制数量仍要分别保存。是否能够根据样品结果判定整批，由批准的方案决定。

Microsoft 的[库存阻止说明](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/inventory-blocking)展示了手工阻止、质量订单阻止和库存状态阻止等不同机制。它也说明抽样配置与阻止范围有关。这个产品实例提醒我们，不能直接把“测了几件”当成“只限制几件”，具体行为需要按配置验证。

| 记录 | 本例需要表达的内容 | 不应据此推断的结论 |
| --- | --- | --- |
| 收货与批次 | LOT-N03，BKT-018，20 件，来源收货行 | 已收货就可领用 |
| 检验任务 | 检验范围、方案版本、项目、样品关联 | 建单就已经完成检验 |
| 结果与复核 | 原始值、单位、要求版本、判定与复核身份 | 单项通过就完成全部质量处置 |
| 处置与放行 | 接受范围、批准身份、条件和有效版本 | 批准后下游一定已应用 |
| 库存与执行状态 | 各系统实际应用范围、其他有效限制 | 解除一项限制就能进行所有业务 |

### 系统名称不能代替责任划分

QMS 通常承接质量规则、检验与不合格处置、纠正措施等业务。LIMS 围绕实验室样品、方法、仪器数据和结果审核组织工作。MES 保存工序执行、现场检验、序列号与返工事实；WMS 控制库存位置和具体收发动作；ERP 则承接采购、生产订单与库存业务结果。实际产品的功能会交叠，也可能由同一套软件完成几个角色。

因此，集成前应逐项确定谁维护要求版本、谁确认结果有效、谁批准本次处置、谁改变库存资格。某套 LIMS 可以配置批次放行流程，某套 ERP 也可以完成来料检验；本文图中的 QMS 放行角色是这组示例的责任安排，实际部署仍按产品能力和企业权限划分。

实验室流程也有适用范围。支架的现场外观或尺寸检查，可以由获准的检验模块直接记录。只有实际需要实验室分析、送样管理或委外检测时，才增加 LIMS 或对应实验室系统。Thermo Fisher 的 [SampleManager 资料](https://tools.thermofisher.com/content/sfs/brochures/BR-80060-LIMS-SampleManager-BR80060-EN.pdf)列出了样品处理、结果审核等能力，可作为这条可选分支的产品参考；不能据此要求每次车间检查都先送实验室。

## 二十件待检支架怎样进入可领库存

### 检验任务从已确认的对象和要求开始

`IQC-0020` 应能追到采购收货行和供应商批次；如果供应商批次与厂内批次不同，保留映射，不能在导入时直接替换。任务还要说明物料与图纸要求的适用版本、方案、检验项目和数量单位。相同物料编码在工程变更前后可能使用不同要求，今天打开最新图纸并不能证明当时检验依据正确。

本例不指定抽样数量和限值。实施时由质量岗位确定方案，并记录检验单位、判定覆盖范围、样品取得方式及适用前提。如果先放行其中一部分，应能指出批准的子范围及对应实物标识；系统和现场无法可靠区分的数量，不宜仅在报表上拆成“已放行”和“待检”。

检验任务的触发点也要写清。采购收货、生产完工或其他事件可能产生检验需求，还需处理重复消息和撤销。Microsoft 的[质量关联文档](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/quality-associations)给出了按业务事件建立质量订单的配置实例，同时存在只创建抽样工作等不同模式。接入时应核对实际生效的模式，不能只看到一张抽样任务就假定库存已经被阻止。

### 结果复核应能追到当时的检验依据

每个结果至少关联任务、检验项目、执行次数、方法与要求版本。数值结果保留单位及判定时使用的精度规则；属性结果保留受控选项。需要设备或人员资格的项目，还应关联当时有效的资格依据。报告附件可以帮助阅读，但最好能从结构化结果定位原始记录，避免只有一份无法核对项目完整性的 PDF。

若任务包含实验室项目，样品身份要能够回到被检批次。取样、交接、接收、分样、检测和剩余样品处理按实际流程保存；一个批次对应多个样品，一个样品产生多个项目结果，都应有明确关系。委外报告还需核对送检对象、方法与适用范围，收到文件不等于已经确认可用于本次处置。

结果异常时先保留原始记录。输入错误可以通过受控更正说明原因；方法执行、样品或设备出现问题，则按适用流程调查并决定结果是否有效。后来取得的通过结果不能自动覆盖最初的失败，也不能依靠反复检测挑选一个满意值。复检为何成立、采用哪项处置授权，以及原结果如何处理，都要能查到。

### 批准接受后还要等待库存应用结果

假设本次所需项目已经完成并有效复核，质量岗位批准接受 `LOT-N03` 的全部 20 件。放行单可记为 `REL-IQC-0020`，引用检验任务与结果版本，记录对象、数量、单位、批准身份和本次要解除的质量限制。

随后向 WMS 发出受控动作，由 WMS 在当前对象版本上应用。本例只有在 WMS 返回业务成功、其他领料条件也满足后，这 20 件才计入可领范围。若仍需从 `QC-01` 移到拣料区，是否允许从当前地点直接发料，以及移库任务完成时点，也要按仓库规则核对。

这条链上的几个时间都值得保留：检验完成、结果复核完成、放行批准、目标应用完成和实际可领。计划员询问“还要等多久”时，才能分辨当前是在等检验、等审批、等接口，还是等现场移库。前文没有给出这些时间的详细实绩，不能把尾批等待的整段时间都归为质量人员审批慢。

## 两台返工风机怎样保留完整质量履历

### 不合格范围先落到序列号

新工单 `MO-0160` 的 160 台风机中，首次终检最终有 158 台通过，两台 `SN001245`、`SN001246` 因支架装配损伤挂起。它们已经装上的支架来自哪些批次，应查实际领料和装配谱系；不能因为尾批有 20 件待检，就推断两台缺陷产品一定使用了 `LOT-N03`。

不合格记录应保存发现工序、缺陷现象、被检对象、检验执行和发现时间。原因尚未确认时就保持待调查。发生了装配损伤，是目前的案例事实；它由何种设备、操作或工艺条件引起，需要另外的证据，不能直接归责给供应商来料。

挂起也要有范围。只限制两台序列号、限制同批产品或暂停整道工序，对交付影响很不一样。扩大隔离应有批准依据，并追到实际受影响的在制品、库存和已经发出的产品；不能把一个模糊的“该型号异常”直接解释成所有库存都不准使用。

### 返工方案、执行记录和复检分别保存

本例批准返工单 `RW-0021`，每台更换一件支架。批准方案需要说明允许的工艺路径、适用对象、拆装要求和复检项目。MES 按方案记录拆下组件、补发组件与重新装配关系，再关联新的检验执行。新补发的两件是额外供给，不能从先前那 160 件支架里重复算出两件。

拆下的两件损伤支架按批准的组件报废处置记录；两台风机经过返工继续使用。产品报废、组件报废、返工与复检是不同对象上的动作，不能在 ERP 成本或质量报表中都汇总成“报废两台”。本案例支架净消耗 162 件，也没有闲置余料退回的主线业务。

| 统计对象 | 数量 | 本例含义 |
| --- | --- | --- |
| 不重复的新风机序列号 | 160 台 | MO-0160 的产品范围 |
| 首次终检通过 | 158 台 | 首次通过率分子 |
| 首次终检未通过 | 2 台 | 两台进入批准的返工流程 |
| 返工后复检通过 | 2 台 | 追加检验执行，不新增产品 |
| 终检执行次数 | 162 次 | 160 次首次执行，加 2 次复检 |
| 最终合格产品 | 160 台 | 两台返工完成后按序列号去重 |

因此，首次通过率仍为 `158 / 160 = 98.75%`。最终合格量达到 160 台，并不会把最初的失败记录改成通过；162 次检验执行也不能作为交付 162 台的依据。后续若追加更多检测，需要按项目与执行类型重新定义统计范围，不能继续套用这张表。

### 复检通过后逐项解除相应限制

质量岗位核对返工完成、规定复检有效、处置条件满足后，再批准两台产品的放行。MES 解除对应执行挂起，WMS 对已经形成库存对象的产品应用相应库存状态；尚未入库的在制品，不能虚构一条库存状态变更成功记录。

如果某台还有独立的工程隔离或客户限制，解除这次不合格挂起不能一并消除它。可以分别保存限制身份、来源、作用范围和解除依据，以当前对象仍生效的限制集合决定允许动作。多个限制覆盖同一批实物时，受限数量应按对象去重或做范围并集，避免直接相加导致“20 件库存被限制了 40 件”。

拒收、让步接受或客户偏差许可属于另外的处置路径。若企业允许这些路径，需要明确适用权限、条件和对象，并保留客户或工程批准等必要依据。本案例没有采用让步接受，不能为了按期交付在界面上直接改成合格。

## 放行指令怎样跨系统落实

### 发送内容应能限定这一次授权

可以把来料放行表达为下面的概念数据。字段为本文示意，不对应任何厂商 API，也没有向真实系统发送指令。

```json
{
  "action_id": "APPLY-REL-IQC-0020-WMS-01",
  "release_id": "REL-IQC-0020",
  "release_revision": 1,
  "inspection_id": "IQC-0020",
  "target": "WMS",
  "object": {
    "plant": "A",
    "material": "BKT-018",
    "lot": "LOT-N03",
    "quantity": 20,
    "unit": "EA"
  },
  "remove_hold_id": "HOLD-IQC-0020",
  "expected_object_revision": "WMS-L03-07",
  "approval_ref": "APP-REL-IQC-0020-01"
}
```

这里的目标是移除指定质量限制，仍须保留其他限制。完整契约还应包含库存维度、必要的子范围标识、要求与结果版本引用、批准凭证验证方式，以及目标不支持部分应用时的处理规则。不能凭消息里自报一个审批编号，就默认调用方具有放行权限。

目标系统要在状态检查和应用之间保证一致性。如果版本已经变化，例如又新增一项隔离，目标应拒绝过期动作或按约定重新核对，避免旧放行覆盖新事实。对外只提供“把状态改成可用”的接口，会让调用方承担很难可靠完成的并发判断。

### 接收成功和业务应用成功分别记录

消息中间件收到消息、接口返回 HTTP 成功、目标完成业务状态变更，是三个不同层面的事实。业务回执需要包含动作身份、实际接受范围、成功或拒绝原因、应用后的对象版本。放行台账据此记录每个目标的落实情况。

假设 MES 已解除两台产品的挂起，WMS 因库存版本冲突拒绝了其中一台的动作。此时显示已经落实的序列号和仍待处理的范围，并按企业规则限制未完成部分的后续动作。不能用一个总的绿色“同步成功”掩盖分歧，也不能未经核实把 MES 的成功记录强行回滚成从未发生。

超时后先按动作身份查询目标。相同身份、相同内容的重试应返回已有结果或安全地完成原动作，避免重复建单和反复改状态。相同身份却换了对象或数量，应明确拒绝；修改放行范围需要形成可审查的新版本，必要时重新批准。

后来发现放行依据无效，则建立新的隔离或撤销动作，核对是否已经领用、装配、发运及其下游谱系。删掉旧放行记录无法撤回已发生的实物移动。需要进一步追溯时，可以沿批次、组件和序列号找影响范围，再按实际权限处理；原始放行与后续纠正都应留下记录。

## 接入时先验证哪些场景

### 用对象和业务回执验收

接口联通后，至少用下面几组用例核对业务结果。均是验收设计，不意味着现有站点连接了这些制造系统。

| 验收场景 | 应能核实的结果 |
| --- | --- |
| LOT-N03 尚有必需项目未完成 | 不生成有效放行批准，库存保持相应质量限制 |
| 全部所需结果有效，批准 20 件 | WMS 应用回执与对象范围一致，其他限制仍保留 |
| 样品结果关联错批次或使用错误要求版本 | 阻止作为该任务的有效放行依据，错误保持可见 |
| 仅批准可明确区分的子范围 | 只有该范围应用成功，其余数量继续受限，数量守恒 |
| 20 件同时存在两项独立限制 | 解除其中一项后仍受另一项约束，不重复累计实物数量 |
| 两台返工后复检通过 | 原失败、返工、组件更换与新结果均可查询，最终产品去重为两台 |
| 消息超时后重复发送 | 同一动作身份不产生第二次业务副作用，可查询原应用结果 |
| 发送后目标新增隔离或版本变化 | 旧动作不能覆盖新限制，冲突进入差异台账 |
| 多目标中只有部分成功 | 按系统与对象显示真实状态，不提前宣称整单落实 |
| 放行后重新隔离 | 保留旧记录，追踪已领用或发运范围，以新授权落实后续动作 |

部分放行还应检查现场标识与拣料扫描。报表正确、标签仍相同，仓库依然可能拿错实物。系统支持的拆批、库存子对象或容器标识，应与现场能够识别的范围一致；无法落实的细分不应留给操作员凭记忆判断。

等待时间可以按任务、结果复核、处置、目标应用分段统计。质量看板还要区分缺陷发生率、首次通过率、复检次数、处置等待与接口未落实数量。指标需要对应对象、时间窗口和状态定义，不能将质量保护动作本身当成缺陷原因。

### Agent 先帮助汇集依据和解释差异

适合先做的能力包括：按批次列出未结项目，关联实验室报告和复核状态，汇总两台产品的返工谱系，解释放行已批准却仍不可领的具体限制，以及将超时动作整理成待核对清单。每项结论返回来源身份、版本、范围和查询时间，缺少依据时明确保留未知。

例如询问“尾批 20 件为什么还不能发料”，回答可以落到 `IQC-0020` 的某项结果尚未复核，或 `REL-IQC-0020` 已批准但 WMS 还未应用。若只查到待检标签，不能进一步编造等待原因和预计完成时间。

写入能力需要复用现有授权与业务条件。Agent 可以整理处置草案、提出复检任务建议或准备放行核对材料；实际批准、放行和重新隔离仍通过已定义的岗位权限和受控动作执行，目标系统继续核验范围与当前状态。自然语言里的“这批没问题，放了吧”不能代替缺失的检验依据。

下一篇进入 EAM 与设备现场状态，继续看设备停机、维修工单、可用资源和生产任务怎样对齐。设备恢复运行之后，还要确认试运行、工艺与质量条件是否满足，才能让计划中的可用产能重新落到现场。
