半导体制造的载具、晶圆与设备事件

从载具槽位、晶圆身份、工艺作业和设备事件出发，拆开半导体自动化中的通信确认、实际处理完成与质量状态，用五片晶圆样本核对重复事件、缺失完成记录和后续放行。

载具已经从设备卸下，里面的每片晶圆是否都完成了本工序？一个作业状态和一条卸载消息，未必能解释漏片、重工或完成事件缺失。需要把载具、槽位、晶圆和工艺尝试分别识别。

本篇展开 I07 的半导体部分，限定为晶圆制造中一次设备处理与结果核对。五片晶圆、槽位和事件均为教学模拟，不代表真实产线接口，也不提供工艺配方参数或完整 GEM300 实现。

先把通信层和业务对象拆开

SEMI 的官方 SECS/GEM 入门说明介绍了 E30 GEM、E5 SECS-II、E37 HSMS 及 GEM300 的相关职责。其公开概述支持区分设备通信、载具管理、处理作业和基板跟踪；详细状态、消息字段和实现一致性仍需所采用版本的标准及设备接口文件。

层次或对象本篇解释范围不能直接推导的结论
E5 / SECS-II消息内容体系任意厂商报告字段都完全相同
E30 / GEM设备通信与控制的一般模型每台设备均实现所有可选能力
E37 / HSMS相关传输通信机制连接存在就等于业务成功
E87 / Carrier载具相关管理载具身份能替代晶圆身份
E40 / Processing工艺处理作业相关管理指令接受就代表处理完成
E90 / Substrate基板跟踪相关信息事件缺失时仍可自动确认去向

表中的中文解释仅概述职责，标准原文仍需单独查阅。本文没有读取付费标准全文，因此不编造具体消息号、强制超时值或状态转换要求。

载具槽位保存当时的实际映射

教学载具 CARRIER-S01 本次只装入五片晶圆，槽位 1—5 对应 W01—W05，属于 LOT-S01。载具是可复用容器，批次和晶圆身份另行保存。装入、槽位确认、设备接收与卸载分别留记录。

槽位晶圆本次工序处理尝试
1W01OP-S10ATT-W01-1
2W02OP-S10ATT-W02-1
3W03OP-S10ATT-W03-1
4W04OP-S10ATT-W04-1
5W05OP-S10ATT-W05-1

槽位映射如果经搬运变化，保存新映射的生效记录，不能用当前槽位回填过去的工艺事件。分批、合批与重入同一工序同样需要批次关系和新的尝试身份，避免把返工覆盖成首次处理。

主机安排 PJ-S01 使用获准配方身份 RECIPE-S / 3，并核对设备、路径和晶圆适用性。配方名称相同不一定代表内容相同，需要设备允许的版本或内容确认机制。本文只保存身份，不提供真实配方内容。

逐片事件证明到哪一步

事件日志对 W01—W04 各有一次开始和一次完成；W05 只有开始。另有 W04 完成消息的一次重发，保留相同来源事件身份。因此共十次送达，九条唯一事件。

十次送达 = 九条唯一事件 + 一次重发
九条唯一事件 = 五次开始 + 四次完成
有完成证据的晶圆 = W01、W02、W03、W04
W05 = 已开始，完成状态待确认

本样本通过稳定 eventId 去重，这个字段属于教学封装，不宣称所有 SECS/GEM 报文都提供同样的全局事件标识。真实接入要按设备日志、会话、报告与业务关联机制确定身份，防止重连、主机重启或序号复用产生碰撞。

W05 的完成事件缺失可能是未完成、事件丢失或状态同步问题。需要查设备结果、当前物料位置与持久日志，不能直接记成报废，也不能因为载具卸下就补一条虚构的成功记录。PJ-S01 在本例验收中保持未全部确认。

处理完成与质量放行分别核对

后续量测结果使 W03 进入待评估隔离。W01、W02、W04 在本例所有所需质量条件均已确认后获准继续，W05 保持完成证据未知。实际量测方法、阈值和放行策略需要产品工程依据，本文没有设定通用良率标准。

五片去向 = 获准继续3 + 质量隔离1 + 完成待确认1
已完成处理4 = 获准继续3 + 质量隔离1

设备轨迹、过程监测、量测和 MES 状态应关联同一次工序尝试。处理完成时间不能自动当成质量放行时间。异常评估若影响同腔体、同配方或同时间窗口其他晶圆，应按证据建立候选集合，不能只按批次名粗略扩大或缩小。

用事件与晶圆集合复算

晶圆事件 JSON包含五个槽位、十次送达及质量状态；校验程序核对事件去重、处理完成集合及三种去向。
