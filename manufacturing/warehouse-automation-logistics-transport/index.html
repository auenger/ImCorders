自动化仓储、厂内物流与运输协同

沿用 60 件支架线边配送与 200 台风机整批交付，拆解 WMS、WES、WCS、车队系统和 TMS 的任务、容器、交接与回执，说明超时重派、途中库存、装车、签收差异和跨系统验收如何落实。

仓库任务已经下发，机器人也到了线边站点，车间却说没有收到指定容器。另一边，成品已经装车，运输平台显示车辆到达客户附近，订单仍然缺少有效签收证据。几套系统里的“完成”，指向的对象和边界并不相同。

这一篇接着 WMS 篇的 60 件支架配送，另加一段假设的自动化搬运过程，再连接原订单 200 台风机的整批运输。设备、任务和容器编号均为模拟，不代表原案例实际部署了机器人或自动化仓库。

先分清库存任务和设备任务

WMS、WES 与 WCS 按实际职责衔接

WMS 管理库存对象、批次、位置与仓库业务任务。WES 常用于协调任务释放、优先级、人员和自动化资源；WCS 常用于设备间的物流控制、路由及执行协调。机器人车队系统则可以承担车辆任务与交通协调，设备控制器处理具体动作和现场状态。

这些能力可能出现在同一套产品中，也可能分开部署，部分系统还会覆盖相邻职责。Honeywell 的仓储自动化产品说明就展示了 WES、WCS、设备控制和监控能力组合的实现。它说明的是一种产品组织方式，不能用来规定所有工厂都必须按相同层级逐层下发。

实施时应逐项确定：谁选择库存，谁拆分任务，谁选择执行资源，谁确认实物交接，谁更新库存，谁向上游返回业务结果。只有这些责任清楚，才知道一个“任务失败”需要由仓库、调度还是设备岗位处理。

一项 WMS 配送任务可以拆成取货、转运和放置等多段执行任务；一台设备也可能连续承接多个业务任务。业务任务、任务段与执行尝试需要映射，不能把设备每次上报的任务号直接当成唯一库存事务号。

容器、库位和设备站点分别映射

容器号标识装载关系，批次标识追溯对象，WMS 库位和设备站点则可能采用不同粒度。一个站点可以服务多个业务位置，设备换站也未必表示库存已经进入最终业务库位。

本例为 60 件支架设置模拟容器 LP-N01-060，从 LOT-N01 的 100 件中按批准规则分出，保留物料、数量、批次与装载关系。容器到站后仍需核对实际身份，不能仅用车辆位置推断它装载了指定批次。

站点映射保存仓库、业务位置、设备站点、关系版本和适用时间。设备地图调整、位置改名或临时封闭后，历史交接仍应按当时关系解释。拆箱、并箱或更换容器时，维护实际装载变化，不能只改界面标签而丢失内容谱系。

任务下发不能越过库存与现场条件

WMS 先核对质量状态、适用批次、占用、源位置和目标需求。WES 或其他调度角色再核对资源能力、站点容量、目标就绪及未结执行。整箱搬运、拆零配送和混装容器，需要各自明确的执行条件。

设备路线可行、通信正常与库存可发是不同条件。上层可以提出配送任务、暂停新任务释放或请求取消，但实际执行仍遵循设备与现场既有的保护和准入流程。一个业务批准记录不能替代这些条件。

完整契约还需需求与任务行身份、批准及限制依据、需要时间、执行资格、交接判定、状态版本和异常处理规则。调度系统可以据此产生多段设备任务，仍须保留同一业务任务的覆盖关系，不因拆段重复增加数量。

接受、到站和交接各自留下证据

任务发送后，接收方可能先返回已接收，再报告执行中、到站、卸载或交接结果。具体状态定义由实际接口决定，不应把任意名为 FINISHED 的字段直接映射成仓库和生产都已完成。

Microsoft 的 MHAX 设备接口说明展示了 WMS 发出工作事件、外部搬运系统回传工作确认或短拣等事件的实现。入站事件可能触发仓库业务动作，配置与数据语义需要逐项核对。仅证明消息已进入队列，不足以证明指定任务已完成业务处理。

移动机器人采用的 VDA 5050 接口说明聚焦车队控制与机器人之间的任务和状态交换。这类接口可以支持执行协同，企业的容器身份、库存位置、线边接收与 ERP 过账仍需另外定义业务关联，不能靠采用某项协议自动补齐。

这些证据可以来自自动识别、设备回报、受控人工扫码或其组合，取决于现场设计。Microsoft 的仓库移动设备配置也列出了位置、数量等工作确认能力。需要多少次确认、由谁执行，应围绕实际风险和业务边界设置，不能把多扫几次码本身当成完整验证。

途中或中转范围是本例用于对账的分类，具体产品可以采用在途位置、任务持载或其他模型。关键是同一份 60 件库存不能同时完整保留在源位、途中和目标位；位置尚不明确时，保留待核对身份和状态，不编造已到位事实。

超时和故障以后怎样恢复任务

先查原动作是否已经发生

收到超时不等于搬运失败。设备可能已经卸载，只是业务回执丢失；也可能已经取走容器，停在中转位置；还可能从未接受任务。恢复前查询原任务、执行尝试、容器当前位置、持载状态与交接证据，无法确定时保留未决并安排核实。

相同身份与内容的重试，应返回已有结果或按原任务安全恢复，不创建第二次独立搬运。事件去重之外，还要检查业务任务与执行范围；设备生成了新的消息 ID，也不能让同一交接被再次扣减库存。

跨系统对账篇讨论的原子标记、目标结果查询和版本冲突处理同样适用。物理搬运无法随数据库事务一起回滚，因此需要把未决结果与恢复依据保留到实际交接范围。

重派和取消保留已执行的任务段

若确认尚未取货，可以按批准规则终止原执行尝试，再将允许范围交给另一资源。若已取货或已到中转站，则从核实后的实际位置安排后续交接，保留已完成段，不能把任务重新标成未开始就再次从源库位取同一个容器。

原任务 60 件需要拆分交付时，父任务与子任务保存数量关系，未完成范围独立可查。拆成 40 件和 20 件只是一个验收分支，不能将两个子任务再加上原任务算成 120 件，也不能把部分成功显示为整笔完成。

取消同样需要区分请求、接受、停止和后续物料处置。尚未执行的任务可以按规则撤回，已经持载或交接的物料则需要确认当前位置与批准去向。取消一条消息不会自动让实物回到原位，库存记录也不能直接复原为从未移动。

调度优化不改变物料资格

中转站满、拣选位缺货、车辆不可用或通道限制，可能让有库存的需求仍然无法立即配送。调度可以调整允许范围内的顺序与资源，必要时请求补货或人工处理，但不得为完成任务使用待检批次、其他订单占用或未经批准的替代物料。

设备恢复以后，再核对任务版本与现场条件。设备篇里的维修完成、批准可用和实际恢复分别保存，不能因为车队系统重新在线就把全部未结任务无条件重发。

成品出厂以后怎样连接运输与签收

包装、装运与运输任务各有对象

沿用原订单整批交付的设定，40 台旧配置合格品与 160 台新配置合格品共同覆盖 SO-200 的 200 台需求。这里不新增实际分批发运，也不将 162 次终检执行误当成 162 台新产品。

WMS 组织成品拣选、包装、集货和装车时，保留产品、序列号、包装或装载单元、订单行及实际数量的关系。包装拆并、换箱和重新贴标，都要维护装载谱系；空托盘或包装数量不能直接当作整机数量。

TMS（运输管理系统）可以组织装载、承运商与运输任务、线路及运输过程等业务。Microsoft 的运输管理概览与装载规划说明展示了装载、发运和运输安排的衔接。具体系统的装载、发运、运输单与运单可能多对多，需要保留明细映射。

装车、出库与承运交接分别确认

运输计划可先于实物齐备形成候选，承运商接受安排也不证明产品已经装上车辆。装车时核对实际产品或容器、装载范围、车辆或运输任务身份及交接要求；短装、换车或装错对象需要留下实际结果。

WMS 与 ERP 应约定哪项事实触发一次出库或发运过账，TMS 的计划完成、车辆离场和承运交接再与它关联核对。不能让 WMS 发运接口与 TMS 出厂事件各自无条件扣减同一笔 200 台库存。

厂内补货和生产配送也不自动触发销售出库。它们可能只改变 WMS 位置，是否同步 ERP 内部转移、由谁触发与怎样归集，按企业库存模型确定；不能把每一段设备动作都映射成独立经营事务。

轨迹到达和客户签收继续区分

在途事件保存来源、运输任务、实际节点、发生与接收时间，以及预计到达的计算依据。车辆进入客户附近或地理围栏，只能提供相应位置证据，不能自动证明指定产品已卸货并由客户接受。

签收记录需要关联收货方、订单或运单明细、实收范围、时间与有效证据。承运平台回传的电子签收、客户确认和 ERP 履行更新，按业务流程核验并取得目标结果；图片附件存在也不等于内容与本订单一致。

可以另设“发运 200 台、确认签收 198 台、2 台待核对”的异常验收分支。198 与 2 的范围要明确且不重复，不能把这两台直接写回仓库当成从未发出，也不能在没有退运实绩时增加退货库存。本分支不改写原案例的整批 200 台交付安排。

签收差异、破损、拒收或退运各自保留原发运与后续处置关系。客户实际签收、订单履行状态与财务确认还可能采用不同规则，本篇不将任一物流事件直接当作财务确认的充分依据。

看板可以分开显示待派发、已接受、实际执行、交接未确认、业务应用未决和客户签收差异。等待时长也沿这些节点计算，并标明所用时间与任务范围，避免只用消息传输耗时解释整段物流延误。

Agent 先定位卡在哪个交接点

面对“这 60 件为什么还没到”，Agent 可以按 MOV-0060 汇集 WMS 分配、执行尝试、设备回报、容器位置、站点确认和库存回执，列出已经成立的事实与仍需核对的范围。只查到车辆到站时，就说明还缺哪些交接证据，不能推断车间已收到指定物料。

面对“这 200 台交付了吗”，继续核对成品明细、实际发运、承运交接和有效签收，并分别说明已取得的证据。预计到达、原客户承诺与实际签收分别展示，来源不明或证据缺失时保留未知。

Agent 可以准备任务查询、差异材料和恢复建议，重派、取消、库存调整或设备控制仍通过各自已有权限与受控流程。写入前检查当前状态及对象版本，结果回到业务台账后再报告完成，不能由自然语言判断直接绕过现场条件。
