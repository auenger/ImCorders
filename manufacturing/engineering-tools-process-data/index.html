研发工程工具与工艺数据如何衔接

沿用风机支架工程变更，拆解 CAD、PDM、PLM 与 CAPP 的文件、零件、结构、工序和指导书关系，说明 CAE 与 CAM 的适用分支，以及版本基线、工艺分配、发布回执和现场偏差怎样受控衔接。

设计人员把新支架图纸签入了资料库，工艺人员还要确认装配顺序、用料位置和检验要求。采购需要识别物料，车间需要打开本次工单适用的指导书。几个人都拿到了“最新版”，仍可能采用了不同组合的定义。

PLM 篇已经讲过支架变更怎样影响库存、采购与工单。这一篇往前补工程工具之间的连接，继续使用 FAN-100 与 BKT-017 → BKT-018 的模拟案例，核对文件、零件、结构、工艺和现场依据如何关联。

一份工程定义由哪些对象组成

CAD 文件与零件对象分别识别

CAD 用于建立几何、装配与图纸等设计内容。PDM 侧重受控管理文件、引用和产品数据，PLM 承接更宽的产品定义与生命周期协作。CAPP（计算机辅助工艺规划）组织制造方法、工序、用料分配与作业要求。实际软件可能合并这些能力，工程对象之间的职责仍需明确。

一件 BKT-018 可以关联原生模型、二维图纸和检验要求，也可能存在不同用途的表示文件。同一文件又可能包含多个配置或关联多个业务对象，具体取决于企业建模方式。文件名、零件号与 ERP 物料号之间，不能只靠字符串相同来认定对应关系。

装配模型里出现的对象也未必都进入产品 BOM。参考几何、布局、工装或展示用对象，需要按明确规则识别；装配中没有建模的胶粘剂等材料，也可能需要在业务结构中受控维护。自动提取能够帮助建立候选，仍要验证数量、对象类型与适用范围。

工程对象本例对应内容需要保存的关联
CAD 文件与引用集合支架模型、二维图和装配引用原生格式、保存版本、依赖及配置
零部件对象BKT-018、FAN-100稳定身份、修订、状态与文件关联类型
工程 BOM 使用关系FAN-100 使用一件支架父子版本、数量、单位和使用位置
工厂制造结构A 工厂制造 BOM 04工程来源、制造组织方式与生效范围
工艺路线与工序R04、OP-030/3工序先后、材料分配、资源与检验要求
作业指导书WI-030/E来源工序、适用配置、受控文件或表示
工单配置与实绩MO-0160 的执行依据绑定的定义版本、实际投入与偏差记录

零件对象描述“这是什么”，结构使用关系还说明“它在这个产品的哪里、用了多少”。同一零件在两个位置出现，若把两条关系按零件号合并，就可能失去安装方向、配置条件或变更影响范围。

文件保存版本与受控修订各有含义

签入一次文件可以形成新的保存版本；受控修订、审批状态和适用范围则需要各自记录。Autodesk Vault 的修订说明区分保存迭代与有里程碑意义的修订。不同产品的命名与流程可以不同，不能把一次保存自动当成制造已获准切换。

本例产品修订为 B，A 工厂制造 BOM 为 04，装配工序为 OP-030/3，路线为 R04，指导书为 WI-030/E。它们属于不同对象的版本。把所有对象统一显示为“B 版”，会丢掉各自的批准和更新历史。

检索也要有上下文。设计人员看到的最新工作版本，可能还在编制；某工单适用的文件则来自已批准基线。对现场提供查询时，应返回工厂、产品配置、工序和生效范围内的版本，并区分工作稿与允许执行的依据。

原生文件、派生表示和引用集合一起核对

装配文件可能引用多个子件、图纸和外部数据。冻结时需要保留实际采用的引用集合，避免打开历史装配时自动加载今天的子件版本。仅存最外层文件，未必能重现当时的设计状态。

PDF、轻量化三维或其他派生表示应关联其来源文件版本和生成记录。派生失败、引用缺失或单位错误，都可能让原生内容和现场表示出现差异。文件哈希可以检查传输与字节一致性，但批准状态、语义完整性和适用性仍需单独核验。

模型中的尺寸、技术要求或三维标注如果参与下游检查，应明确以哪个受控对象为依据、如何映射特征身份及单位。界面能显示模型，不代表已经完整保留所有制造和检验含义。

工程结构怎样转换成工厂的制造定义

工程 BOM 与制造 BOM 保留位置关系

工程 BOM 按设计组成表达产品，制造 BOM 按工厂实际组织表达用料与装配层级。本例仍然是一台风机使用一件新支架；A 工厂可以把它安排在整机装配段，其他工厂是否采用预装组件，需要另行定义。

转换时保留工程来源对象、版本和使用路径，以及对应制造对象、版本和位置。PTC 的制造关联说明分别描述零件等效、使用关系和出现位置等关联类型，说明对象对应与位置对应可以有不同粒度。本文采用这种分层核对思路，不要求其他系统使用相同链接名称。

映射可以包含重组、拆分和合并，但必须说清数量与范围。工程结构里两处使用同一标准件，制造侧可以汇总备料，仍要能回到原使用位置；某厂增加中间装配层级，也要区分它是制造组织节点，还是需要建立独立库存身份的半成品。

材料增加与制造转换需要依据

制造可能增加过程材料、损耗或包装项目，但每项都要有业务含义。哪些进入产品，哪些属于过程消耗，哪些是工装或可重复使用的资源，需要按企业规则分类，避免在 BOM、工序和仓库里重复扣账。

用量换算还需固定基准：每台、每批还是每次准备；净用量、毛用量和损耗率如何解释；单位与精度怎样处理。本文不增加具体损耗参数，也不把实际返工的额外两件支架回填成每台产品的标准用量。

前文 160 台新风机的标准支架需求仍是 160 件。后来两件组件装配损伤，按批准流程追加供给并消耗，最终净耗用 162 件。这是执行偏差及其处置。若后续希望据此改变标准工艺或用量，需要另外评估，不能直接用一次实际记录覆盖工程定义。

工程变更后逐项检查制造关联

BKT-017 改为 BKT-018 后，既要检查零件和文件，也要检查制造使用位置、工序分配、资源兼容、指导书和检验要求。图纸批准并不能证明这些关联都已经更新。

同一零件被多种产品或工厂使用时，工程使用关系提供影响候选。是否需要切换，继续结合产品配置、互换性、采购与在制状态判断。原案例的旧工单 MO-0040 与新工单 MO-0160 保留各自依据，不能因为新版本发布就改写已开工产品的历史。

并行变更也需要可见。若制造岗位已经在另一基线上修改路线，新工程变更到达时应比较差异，保留冲突和评审记录。按“最后保存时间”覆盖整套制造结构，会让另一项合法修改丢失。

CAPP 要把工艺落实到什么粒度

工序既关联用料，也关联被加工对象

工艺规划需要说明做什么、按什么顺序、使用哪些材料和资源，以及怎样检验。路线、工序、工步等层级由企业和系统确定，不能仅用一张顺序表代替全部要求。返工或备选路径还要说明进入条件与允许范围。

将支架分配到 OP-030/3，需要指出来自制造 BOM 的哪条使用关系、分配多少、何时投入，以及适用哪项配置。材料已经在前一道工序投入、后一道工序只是继续操作这个组件时，不应因为再次关联它就自动再领一次料。

PTC 的工序零件分配说明区分来自 BOM 的分配和被操作对象等情形。接入时需要核对来源关系和操作含义，不能把每条工序关联都解释为新增材料消耗。

工序分配完整性也应按对象类型检验。材料漏分配、重复分配与仅作参考的对象含义不同；允许分次投入时，分配量总和与标准用量、批量和批准规则一致。不能简单要求“每个对象只出现一次”，否则会误判合法的分步加工。

工装、能力、人员与检验要求分别配置

工装和设备需要能力与适用关系，不应只填一个显示名称。可以定义允许的资源或资格条件，再由现场或排程选择符合条件的具体资源；计划中的能力要求与实际使用的设备身份分别保存。

人员技能、工装有效性、计量设备状态和所需检验项目，按适用业务纳入作业前置条件。设计给出某项特征要求，工艺再规定如何形成与检验它，质量流程确认结果；特征身份、方法、单位和要求版本需要保持关联。

工时也要注明准备、加工、每件或每批的基准及估计依据。APS 篇使用的是独立小时样本，不能把那组模拟时长自动写成这里的标准工艺参数。下游如果按不同批量或效率换算，应保留规则和版本。

指导书与 CAE、CAM 按实际范围衔接

指导书可以由工艺数据生成，也可以是受控编制的文件。PTC 的工艺规划说明展示了工序、材料分配、资源与文档共同形成作业指导信息的实现。界面采用 HTML、PDF 或三维方式，不改变它需要关联来源工序、固定版本与适用范围的要求。

CAE 仿真应保存所用几何与配置、材料假设、边界条件、求解设置和结果评审。它可以提供设计验证依据，是否满足某项验收要求仍取决于批准的方法和适用范围，不能直接当作每台产品的实测检验结果。本例没有新增一项已完成的支架仿真。

CAM 在存在机加工等需求时，继续关联制造模型、毛坯、装夹、刀具、机床与后处理配置，形成相应的刀路或程序及验证记录。程序需要受控发布、适用性确认与现场版本核对；上层文件已下载不代表设备已经加载或执行了正确程序。Autodesk 的 NC Program 说明展示了刀路、机床与后处理配置共同参与程序输出的实例。

本组主案例通过采购获得支架，没有设定厂内机加工过程。CAM 在此作为按需分支说明，不给 BKT-018 虚构机床、切削参数或加工实绩。工艺平台能够管理多种对象，也不意味着每件物料都要完整经过 CAD、CAE、CAM 再投产。

发布包怎样让下游拿到同一组定义

先固定范围、对象与依赖清单

本例新工单采用产品 B、A 工厂制造 BOM 04、路线 R04、装配工序 OP-030/3 和指导书 WI-030/E。序列号范围仍为 SN001201 至 SN001360，旧工单的 40 台按既有批准依据处理；旧料与采购调整沿用前文，本文不重新决定处置。

发布清单可以表达为下面的概念结构。编号和字段用于说明对象关联，不对应厂商接口，也没有执行真实发布。

{
  "package_id": "ENG-ECN042-A-01",
  "package_revision": 1,
  "change_ref": "ECN-042",
  "plant": "A",
  "product": { "id": "FAN-100", "revision": "B" },
  "manufacturing_bom": { "revision": "04" },
  "routing": { "revision": "R04" },
  "operation": { "id": "OP-030", "revision": "3" },
  "work_instruction": { "id": "WI-030", "revision": "E" },
  "scope": {
    "production_order": "MO-0160",
    "serial_from": "SN001201",
    "serial_to": "SN001360"
  },
  "material_allocation": {
    "material": "BKT-018",
    "quantity_per_product": 1,
    "unit": "EA"
  }
}

完整契约还需要制造 BOM 与路线的稳定对象身份、源目标映射、使用位置、文件及依赖集合、批准凭证、预期目标版本和发布动作身份。这里省略未在案例中定义的对象编号，不能据此直接调用一个只接受版本号的接口。

固定清单使接收方能够核对这次发布的内容。依赖对象尚未创建、文件未准备好或基线不同，都应返回明确结果。结构化数据与文件分开传输时，还需追踪双方落实情况，避免 BOM 已更新、现场指导书却仍取到旧表示。

ERP 与 MES 分别返回业务结果

ERP 可以接受制造结构与路线映射，MES 则要继续检查工单、在制状态、工序配置和文件准备。目标对象有各自的业务条件，包已送达不能作为统一的“切换完成”。

同一包在 ERP 成功、MES 拒绝时，台账保留双方接受范围、目标版本、拒绝原因和待处理对象。按批准方案解决依赖或冲突后，再对未落实范围补发；相同动作与内容重试时查询已有结果，不重复创建结构或绑定。

迟到旧包不能覆盖已经应用的新基线。若工单已经开工，后续修改按授权的工单变更或返工流程核对，并保留原执行依据。跨系统对账篇的身份、版本和未决结果规则，同样适用于工程发布。

现场副本与已执行依据也要保留

操作员需要打开工单绑定的文件，并能识别版本和适用范围。纸张、离线终端缓存和下载副本若参与执行，应有受控发放、更新和过期处理办法，不能只确认服务器文件已换新。

如果现场在离线期间收到新发布，旧副本是否仍允许完成当前任务，需要批准规则。恢复联网后核对实际使用版本、执行范围和待处理差异。仅删除旧文件，无法撤销已经发生的装配、检验或设备程序执行。

现场发现指导书描述不清，可以关联工单、工序和文件版本反馈。临时处置按授权记录其范围和有效期，长期修改再经过工程与工艺评审形成新基线；便签或聊天里的修改不会自动变成标准作业要求。

接入以后怎样确认工程链条没有断开

验收要覆盖对象与关系的变化

以下用例验证设计，不代表站点已经集成真实工程软件。除了能否打开文件，还要检查对象关系、目标回执与实际采用依据。

验收场景需要核实的结果
原生装配引用旧子件，目录已有新文件冻结基线仍能找到当时引用，不自动替换历史依赖
新保存版本尚未批准可作为工作记录，不能作为已批准制造切换依据
同一零件在两个使用位置出现保留位置及数量关系，变更影响不因合并而丢失
制造结构重组或增加中间层级可追到工程来源，数量与组织节点含义明确
工序再次操作已投入组件区分被操作对象与新增消耗，不重复扣料
材料分次投入或缺少工序分配按批准规则检出漏配、重复与合法拆分
设计要求、工艺与检验版本不一致阻止相应发布或执行，标出不一致对象
派生文件生成失败或来源版本错误不把文件存在当成就绪，依赖差异可查询
ERP 应用成功而 MES 文件未就绪各目标真实结果可查，切换未完成部分保持可见
同一包重发或迟到旧包到达不重复建对象，不覆盖更新基线
已开工工单申请变更保留历史依据，走受控变更与在制处置
离线终端仍有旧指导书核对副本及实际使用范围，不仅检查服务器链接
两件返工额外消耗留在实绩与处置记录，不自动改变每台标准用量
按需使用 CAE 或 CAM来源配置、验证与批准范围可追溯，缺少证据保持未决

可以用原案例做一次关联核对：产品 B 对应哪些文件，制造 BOM 04 的支架使用位置映射到哪项工序，WI-030/E 引用哪份工艺基线，MO-0160 实际绑定和读取了什么。任一步无法回答，就把缺失对象和责任岗位列入待处理清单。

Agent 先做关联核查和评审材料

Agent 可以比较两组工程基线，汇集受影响的制造位置、工序和文件，检查发布依赖与目标回执，再生成带来源的差异清单。查询需要产品配置、工厂、版本和生效范围，返回时注明来源身份、查询时间和未知部分。

问“新支架能否直接投产”，至少要核对设计与工艺批准、适用范围、制造对象准备和目标落实情况。只有图纸已批准时，就先报告这一项事实，不能扩展为车间所有条件已经满足。仿真通过、文件下载成功或模型名称相同，也各自只能证明其范围内的结果。

自动生成工艺或指导书可以作为候选材料，仍需相应专业岗位检查对象关联、方法与要求。发布、批准和现场控制沿用已有权限；模型提出一项参数或刀路建议，不会因此获得执行资格。
