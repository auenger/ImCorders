整理制造业 FDE 专项课程时，我先选了 PLM、ERP、APS、MES、QMS、WMS、SCADA 和 EAM。这些系统足以串起一条生产链，也留下了不少需要继续研究的问题。图纸怎么变成工艺？库存有货为什么还缺料？检验合格以后，谁有权放行？

我在个人站持续拆解制造业系统。这篇记录研究范围、已发布文章和仍待补齐的问题，作为可以回查的总目录。主要面向进入制造现场的 AI 工程师、FDE、产品经理和技术负责人，也供我自己安排选题、补资料和记录进度。

截至 2026 年 10 月 15 日，[制造业系统模块](/manufacturing/)已有 18 篇内容，包含 1 篇总地图与 17 篇专题。M01 至 M10 十个领域均有文章涉及，首轮系统专题已发布；细分能力、完整业务场景和行业差异仍需继续补充。文末分别登记已发布内容和下一轮选题。

[制造业系统数据地图](/manufacturing/data-map/)保留五张 Archify 数据流图，并已在页面顶部嵌入 [Factory Systems Atlas 空间图谱](/manufacturing/systems-atlas/)。空间图谱可切换五个业务视图、浏览九个区域和关系契约。它帮助定位系统与数据交接，布局与动画均为示意，未接入真实工厂数据。

## 这份地图怎样使用

制造业很难有一张永远完整的系统清单。机械加工、电子装配、食品、制药和化工的业务对象差异很大，同一项能力也可能属于不同产品。本文覆盖计划研究的主要系统族及必要的支撑能力，后续遇到行业专用系统再补充。

阅读时可以从下面十个领域进入。编号用于长期维护，后续增加内容时保留已有编号；领域链接跳到本文对应目录；文末的覆盖核对表与发布清单提供独立文章入口。

| 编号 | 领域入口 | 要追踪的业务变化 |
| --- | --- | --- |
| M01 | [研发设计与产品数据](#m01) | 需求变成产品定义、图纸、BOM 和工艺 |
| M02 | [客户、供应商与经营管理](#m02) | 商机变成订单，需求变成采购与经营账目 |
| M03 | [计划排程与生产执行](#m03) | 订单变成可执行任务，现场动作变成生产记录 |
| M04 | [仓储、厂内物流与运输](#m04) | 物料到厂、入库、配送、消耗，成品出厂 |
| M05 | [质量、实验室与追溯](#m05) | 检验结果进入处置、放行、改进和召回判断 |
| M06 | [设备、维护与工厂资源](#m06) | 设备和辅助资源从可用走到维护、恢复或退出 |
| M07 | [现场控制与工业数据采集](#m07) | 控制指令作用于设备，信号形成可解释的记录 |
| M08 | [能源、安全与环境](#m08) | 资源消耗、作业风险和环境数据进入管理流程 |
| M09 | [数据、集成与工业智能](#m09) | 分散记录形成可关联、可计算、可核查的数据 |
| M10 | [组织协同、售后与运行支撑](#m10) | 人员、文件、服务与系统运行支撑生产协作 |

这里同时列出软件系统、功能模块、工程工具和控制设备。它们在制造现场都需要理解，但并不处于同一个层次。MRP 是物料需求计划能力，PLC 是控制器，OPC UA 是工业互操作相关标准与技术体系，不能按三个平级业务系统来设计架构。

[ISA-95](https://www.isa.org/standards-and-publications/isa-standards/isa-95-standard)提供了企业与控制系统集成、制造运营活动建模的参考。本文的十个领域是为专栏组织内容所做的分类，不对应十个标准层级，也不代表工厂需要分别采购十套产品。

## 按业务领域拆开系统

<a id="m01"></a>

### M01 研发设计与产品数据

产品进入车间前，需要先把“做什么”和“怎样做”定义清楚。这一组从工程工具一路延伸到产品数据和工艺管理。

| 系统或能力 | 主要研究范围 | 后续要追问的问题 |
| --- | --- | --- |
| CAD，计算机辅助设计 | 二维图纸、三维模型、装配结构 | 模型、图纸与物料版本怎样对应？ |
| CAE，计算机辅助工程 | 结构、热、流体等仿真分析及结果 | 仿真使用的模型、参数和实测结果怎样留档？ |
| CAM，计算机辅助制造 | 加工策略、刀具路径、数控程序生成 | 工程文件怎样变成指定机床可执行的程序？ |
| PDM，产品数据管理 | 设计文件、版本、签入签出、审批 | 谁能修改，谁发布，现场拿到的是哪个版本？ |
| PLM，产品生命周期管理 | 产品结构、BOM、配置、变更、生命周期协同 | 一次工程变更会影响哪些物料、订单和在制品？ |
| CAPP，计算机辅助工艺规划 | 工艺路线、工序、工时、工艺文件 | 工艺规划如何接到执行系统，现场变更怎样反馈？ |
| 配方研发与规格管理 | 配方、原料规格、试验、放大及批准 | 实验室配方如何转成工厂可执行的生产定义？ |
| 工程仿真与虚拟调试 | 产线布局、物流仿真、设备行为验证 | 模型的假设怎样与现场测量结果核对？ |

这一组会重点拆 EBOM（设计物料清单）、MBOM（制造物料清单）和工艺之间的关系。清单的转换、维护和发布位置要结合企业部署确认，不能只凭 PLM、ERP 或 MES 的名称判断数据归属。产品生命周期的通用范围可参考 [SAP 的 PLM 介绍](https://www.sap.com/sea/resources/what-is-product-lifecycle-management)。

<a id="m02"></a>

### M02 客户、供应商与经营管理

订单进入工厂之前，销售可能已经做出交期承诺；生产开始之前，采购也可能已经锁定供应商。研究这一组，需要把这些承诺带进后面的计划和执行过程。

| 系统或能力 | 主要研究范围 | 后续要追问的问题 |
| --- | --- | --- |
| CRM，客户关系管理 | 客户、商机、需求、销售协作 | 销售承诺如何传到计划与生产岗位？ |
| CPQ，配置、定价与报价 | 产品选配、约束、报价、审批 | 客户选出的配置能否设计、采购和生产？ |
| ERP，企业资源计划 | 销售采购、物料、生产订单、库存核算、成本财务 | 订单、物流和财务记录如何关联与对账？ |
| SRM 与采购协同 | 供应商准入、寻源、询报价、交付与绩效 | 供应商确认的到货日期是否进入缺料判断？ |
| SCM 与供应链计划平台 | 需求、供应、库存、网络协同 | 哪些属于计划能力，哪些属于执行和伙伴协作？ |
| EPM 与经营分析 | 预算、预测、盈利和经营绩效 | 订单毛利如何受到良率、返工和实际耗料影响？ |

SCM（供应链管理）覆盖的范围很宽，在具体企业里可能由多个系统共同承接。ERP 也可能带有仓储、质量或设备模块。[SAP 对 ERP 的介绍](https://www.sap.com/sea/resources/what-is-erp)强调跨业务流程的集成；后续拆解会落实到企业启用了哪些模块、哪些记录仍在外部系统。

<a id="m03"></a>

### M03 计划排程与生产执行

这一组最适合用一张生产订单贯穿。订单怎样展开需求，什么时候下达，谁领取任务，缺料或停机以后如何调整，都需要留下状态和时间。

| 系统或能力 | 主要研究范围 | 后续要追问的问题 |
| --- | --- | --- |
| S&OP / IBP，产销协同与集成业务计划 | 需求预测、产能、库存与经营目标协调 | 月度供需判断如何约束车间的短期计划？ |
| MPS / MRP，主生产计划与物料需求计划 | 产品计划、BOM 展开、净需求、采购和生产建议 | 提前期、批量、库存口径变化会怎样影响结果？ |
| APS，高级计划与排程 | 有限产能、物料、换型、日历及优先级约束 | 排出的计划有哪些假设，插单以后如何重排？ |
| MES，制造执行系统 | 派工、过站、报工、在制品、消耗、返工与追溯 | 一件产品当前在哪道工序，下一步允许做什么？ |
| MOM，制造运营管理 | 生产、质量、维护、库存运营之间的协同 | 运营范围怎样由 MES 和周边模块共同实现？ |
| 电子作业指导与 Andon | 作业步骤、现场异常呼叫、响应和升级 | 操作版本、异常处理与工单怎样关联？ |
| 批次执行与电子批记录 | 配方执行、批次步骤、过程记录、复核 | 暂停、偏差、补录和复核会留下什么证据？ |

MRP、APS 和 MES 的结果需要相互核对。物料需求计划算出“需要多少”，排程还要考虑资源和时间，执行系统再记录现场发生了什么。具体能力的交叉范围随产品而变，可对照 [Siemens APS](https://www.siemens.com/en-us/products/opcenter/advanced-planning-scheduling-aps/) 和 [SAP MES](https://www.sap.com/uk/resources/what-is-mes) 的说明阅读。

MOM 在本文中作为制造运营的较宽范围使用，不预设企业必须在 MES 之外再安装一套 MOM。

<a id="m04"></a>

### M04 仓储、厂内物流与运输

“仓库里有货”和“这个工单现在可以领料”之间，还隔着检验、冻结、分配、库位和配送状态。

| 系统或能力 | 主要研究范围 | 后续要追问的问题 |
| --- | --- | --- |
| WMS，仓储管理系统 | 收货、上架、批次库位、拣选、退料、盘点 | 实物位置、业务可用量与 ERP 库存账如何核对？ |
| WCS，仓储控制系统 | 输送线、堆垛机等自动化设备任务控制 | 搬运指令执行失败或重复回报时怎样处理？ |
| WES，仓储执行系统 | 仓内任务、人员和自动化资源协调 | 波次、任务和设备能力如何动态衔接？ |
| 厂内配送与电子看板 | 线边补料、拉动配送、空容器回收 | 补料由什么触发，送达如何确认？ |
| AGV / AMR 车队调度 | 搬运任务、路径、交通、充电和车辆状态 | 物流任务完成如何回写业务单据？ |
| YMS，园区与场站管理 | 预约、车辆入场、月台、装卸和出场 | 厂门、月台与仓库各自确认哪个时间点？ |
| TMS，运输管理系统 | 承运、配载、路线、在途、签收和运费 | 出库到客户签收之间的责任怎样追踪？ |

WCS、WES 和车队调度产品存在功能交叉，后续按任务分配、设备控制和完成确认来拆边界。仓储和运输的基本范围分别参考 [SAP WMS](https://www.sap.com/india/products/scm/extended-warehouse-management/what-is-a-wms.html) 与 [SAP TMS](https://www.sap.com/resources/what-is-a-transportation-management-system-tms)。

<a id="m05"></a>

### M05 质量、实验室与追溯

质量记录要能一路追到处置决定。测量合格、检验单完成、批次放行和库存解除冻结，是需要分别检查的动作。

| 系统或能力 | 主要研究范围 | 后续要追问的问题 |
| --- | --- | --- |
| QMS / eQMS，质量管理系统 | 检验计划、不合格、纠正预防、审核、客诉 | 问题怎样分派、处置、验证并关闭？ |
| LIMS，实验室信息管理系统 | 样品、检测任务、方法、仪器、结果和报告 | 样品和生产批次如何对应，复测怎样留痕？ |
| SPC，统计过程控制 | 控制图、过程波动、异常规则和响应 | 统计异常如何触发现场调查与处置？ |
| 质量策划与分析工具 | APQP、FMEA、控制计划、MSA 等方法的数字化支持 | 风险和测量能力判断怎样影响检验与作业要求？ |
| 检测设备与结果采集 | AOI、测试台、计量设备、视觉检测结果 | 检测程序版本、测量值和产品身份怎样绑定？ |
| 产品谱系与追溯平台 | 批次、序列号、投入产出关系、去向追踪 | 分批、合批、返工后能否完整还原关联？ |

SPC、FMEA 等是方法或能力，可以作为 QMS、MES 的模块实现。独立追溯平台也需要依赖生产、仓储和检测系统留下的原始记录。LIMS 的样品和检测流程可参考 [Siemens Opcenter Laboratory](https://www.siemens.com/en-gb/products/opcenter/research-development-laboratory/laboratory/)。

<a id="m06"></a>

### M06 设备、维护与工厂资源

设备停机以后，要同时看现场状态、维修记录和计划影响。工单写着“维修完成”，还需要确认设备是否经过验证、何时恢复生产资格。

| 系统或能力 | 主要研究范围 | 后续要追问的问题 |
| --- | --- | --- |
| EAM，企业资产管理 | 资产台账、生命周期、维护、备件和成本 | 设备从购入到退役的记录怎样连续保存？ |
| CMMS，计算机化维护管理 | 点检、保养、维修工单、人员和备件 | 异常如何转成工单，维护窗口如何与生产协调？ |
| APM，资产绩效管理 | 资产健康、可靠性、风险和维护策略 | 健康判断有什么依据，如何形成可执行维护任务？ |
| 状态监测与预测性维护 | 振动、温度等信号与故障预测 | 数据异常、模型告警与设备故障怎样区分？ |
| 刀具、模具与工装管理 | 寿命、位置、领用、维修和配套关系 | 缺少可用工装会怎样影响排程与质量？ |
| 计量校准与设施管理 | 校准周期、量具状态、公用设施维护 | 量具超期后，哪些检测记录需要回查？ |

EAM 和 CMMS 的覆盖范围有重叠。一般可以从资产全生命周期与日常维护任务两个视角进入，但仍要逐项核实实际产品功能。参考 [IBM EAM](https://www.ibm.com/think/topics/enterprise-asset-management) 和 [IBM CMMS](https://www.ibm.com/think/topics/what-is-a-cmms)。

<a id="m07"></a>

### M07 现场控制与工业数据采集

这一组需要和业务交易系统分开理解。设备的一次状态变化、控制程序的一次扫描、MES 的一次报工，可能采用完全不同的时间尺度。

| 系统或组成 | 主要研究范围 | 后续要追问的问题 |
| --- | --- | --- |
| PLC / PAC，工业控制器 | 逻辑、顺序、联锁、输入输出与设备控制 | 哪些动作由本地控制逻辑决定？ |
| DCS，分布式控制系统 | 过程控制、操作、控制回路和工程配置 | 连续过程与批次过程怎样运行和切换？ |
| SCADA，监控与数据采集 | 设备监视、报警、趋势、远程操作 | 点位对应什么设备，数据质量和报警如何处理？ |
| HMI，人机界面 | 操作画面、状态显示、参数输入 | 操作员看到的状态与上层系统是否一致？ |
| CNC / DNC 与机器人控制 | 数控加工、程序传输管理、机器人动作 | 程序版本、设备执行和产品记录怎样关联？ |
| Historian，工业历史数据库 | 时序记录、事件、质量标记、历史查询 | 采样、压缩和时间戳怎样影响事后分析？ |
| 工业网关与边缘采集 | 协议适配、点位采集、缓存和断网续传 | 网络恢复以后如何识别补传、乱序与缺失？ |
| SIS，安全仪表系统 | 安全相关检测、逻辑与保护动作 | 与基本过程控制、管理系统的职责如何区分？ |

PLC、DCS、SCADA 属于工业控制相关技术，架构和组合随现场变化，可参考 [IBM 对 OT 的介绍](https://www.ibm.com/think/topics/operational-technology)。专栏会讨论它们如何提供状态和证据；涉及生产控制或安全保护的动作，需要单独分析工程约束，不能沿用普通业务单据的审批模型。

<a id="m08"></a>

### M08 能源、安全与环境

工厂还要管理电、水、气、蒸汽、作业风险和环境影响。这些信息需要和班次、产量、设备及具体作业关联。

| 系统或能力 | 主要研究范围 | 后续要追问的问题 |
| --- | --- | --- |
| 能源管理系统 | 分项计量、能源平衡、需量和能效分析 | 单位产品能耗怎样分摊，停机能耗记到哪里？ |
| 公用工程与楼宇管理 | 暖通、空压、供水、冷却等设施监控 | 公用设施异常会影响哪些产线？ |
| EHS，环境、健康与安全管理 | 风险、事件、检查、整改、培训 | 风险记录如何与人员、设备和作业任务对应？ |
| 作业许可与承包商管理 | 检修等作业申请、条件确认、交接和关闭 | 作业开始前有哪些条件必须经责任人确认？ |
| 环境监测与碳数据管理 | 排放、废弃物、核算边界与因子版本 | 数据从哪里来，计算和审核如何复核？ |

EMS 在不同语境下可能表示能源管理或环境管理，后续文章会写清全称。这里先记录系统范围，具体行业的规则和核算方法将在专题中另查适用依据。

### M09 数据、集成与工业智能

跨系统问题经常卡在最普通的字段上。同一物料有多个编码，同一工单在两个系统里状态不同，一条补录记录又可能比实际发生时间晚几个小时。

| 系统或能力 | 主要研究范围 | 后续要追问的问题 |
| --- | --- | --- |
| MDM，主数据管理 | 物料、组织、客户、供应商、设备编码与维护流程 | 哪个角色维护哪些字段，分发失败怎样处理？ |
| API、ESB、iPaaS 等集成设施 | 接口、服务编排、转换、连接器 | 接口失败时谁重试，如何防止重复写入？ |
| EDI 与伙伴数据交换 | 客户、供应商之间的结构化业务消息 | 消息送达和业务接受如何分别确认？ |
| 消息平台、ETL / ELT、CDC | 事件传递、批量加工、数据库变更捕获 | 顺序、删除、补传和重放怎样处理？ |
| IIoT，工业物联网平台 | 设备接入、资产模型、遥测与应用连接 | 点位数据如何关联到具体设备和业务对象？ |
| 数据仓库、湖仓与治理平台 | 数据建模、目录、血缘、质量和访问控制 | 分析结果能否回到原始记录与计算口径？ |
| BI、经营看板与过程分析 | 指标、报表、事件分析、流程瓶颈 | 同一个良率、交付率或 OEE 为什么算出不同结果？ |
| 数字孪生与仿真平台 | 实体映射、模型状态、仿真与现场反馈 | 哪些结果来自实测，哪些来自模型假设？ |
| 工业 AI 与 Agent 运行平台 | 模型、知识检索、工具、任务、评估和审计 | 结论有没有证据，动作是否在授权范围内？ |

OPC UA、MQTT、Modbus、工业以太网，以及行业专用通信接口，会放在这一组与现场采集专题的交叉部分。它们承担的通信与建模能力不同，接通协议之后仍需定义业务语义。[OPC Foundation 对 OPC 的介绍](https://opcfoundation.org/about/what-is-opc/)可作为工业互操作部分的起点。

## 每个专题准备写到什么程度

系统介绍之后，需要有可核对的业务过程。以 MES 为例，我希望读者能跟着一张工单，看到派工、领料、过站、报工、返工和完工入库，并理解每一步为什么允许或拒绝。

每个专题按下面这些问题准备材料，篇幅较长时拆成多篇，内容仍归到同一个目录编号下。

| 分析部分 | 要留下的内容 |
| --- | --- |
| 使用者与责任 | 谁录入、谁执行、谁审批、谁核对，以及他们依赖的结果 |
| 对象与状态 | 单据、主键、版本、字段口径、状态流和对象关系 |
| 正常与异常流程 | 一条完整案例，以及撤销、返工、补录、重复和冲突情况 |
| 系统边界与接口 | 数据所有者、上下游、交换频率、失败处理与对账方式 |
| 实施与验证 | 主数据准备、历史数据、现场操作、迁移和验收案例 |
| Agent 接入 | 可读证据、可用工具、写入约束、人工决策点与评估样例 |

示例数据会标明为模拟数据；公开案例注明出处；项目经验则交代适用背景和无法公开的范围。产品文档可以帮助确认能力，但“某产品支持”不能直接推导成“所有企业都这样部署”。

Agent 部分从证据查询开始。订单交期分析至少要保留来源系统、对象标识、业务发生时间、读取时间和适用版本。发现库存与报工冲突时，应把差异暴露出来，再由明确的业务规则或责任人判断。释放工单、调整库存、修改主数据和操作设备会分别讨论，不能仅按“是否调用成功”验收。
